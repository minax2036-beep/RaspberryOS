# RaspberryOS 基本仕様書

- 文書バージョン：0.1-draft
- 対象：Raspberry Pi 5（BCM2712 / AArch64）
- 開発状態：初期カーネル骨格の実装開始

## 1. 目的

RaspberryOS は Linux カーネルを基盤にせず、独自カーネルから段階的に開発する OS である。最終的には、ユーザーがシェル、設定ファイル、アプリ、システムサービスなどを自由にカスタマイズできることを目指す。

## 2. 開発方針

- ソースコードと日本語の仕様書を GitHub で管理する。
- C++ を主言語とし、CPU 初期化など必要な箇所だけ AArch64 アセンブリを使う。
- 小さな段階に分け、各段階でビルドとテストを行う。
- CI のビルド成功と Raspberry Pi 実機での起動成功を区別する。
- 初期の実機テストでは既存 OS の起動ファイルを上書きしない。

## 3. 起動方式

Raspberry Pi の EEPROM ブートローダーとファームウェアを起動経路の一部として利用し、その後に独自カーネルへ制御を渡す。Raspberry Pi 5 の標準的なファイル名は kernel_2712.img で、存在しない場合は kernel8.img にフォールバックする。実際の起動条件、ロードアドレス、CPU 例外レベル、Device Tree の受け渡しは実機検証を通して確定する。

## 4. 言語とビルド

- カーネル：C++20 を基本とする。
- アセンブリ：AArch64。
- ビルド：Linux 上の AArch64 クロスコンパイラー。
- 初期段階では例外、RTTI、通常の OS ランタイムへの依存を無効にする。

## 5. 機能ロードマップ

1. ビルド可能な最小カーネル骨格。
2. 起動時状態の検証と診断出力。
3. Raspberry Pi 5 向けの文字出力・入力バックエンド。
4. 基本的なメモリ管理と例外処理。
5. シェルと基本コマンド。
6. ファイルシステムと設定管理。
7. アプリ起動管理プログラムと独自 .xid 実行形式。
8. ユーザー権限、プロセス分離、システムサービス。
9. デバイス管理、追加ドライバー、必要に応じて GUI。

## 6. アプリ権限と起動

アプリごとの権限設定は、将来的にシェルコマンドと設定ファイルの両方から変更できるようにする。AppLauncher は設定の読み込み、権限ポリシーの判定、実行形式の検証を担当する。ただし、ユーザーアプリからの要求を最終的に許可・拒否し、CPU の特権状態とメモリ保護を強制する責任はカーネルに置く。

通常アプリは EL0 で実行することを基本とする。EL1 はカーネルと同等に近い特権を持つため、単なる一般アプリの権限切り替えとしては扱わない。特権コードの実行方式は、保護機構と信頼境界を設計した後に決定する。

## 7. 独自 .xid 形式

.xid は RaspberryOS 向けアプリケーション形式の候補である。マジック値、バージョン、対象アーキテクチャ、コード・データ領域、エントリーポイント、サイズ検証などを定義する。初期段階では形式と ABI の設計を優先し、実行機能はローダーとメモリ保護が整ってから実装する。

## 8. 現在未実装の機能

シェル、ファイルシステム、UART 出力、ディスプレイ、入力、メモリ管理、アプリ起動、権限設定、.xid ローダーはまだ実装されていない。現時点のカーネル骨格は待機ループのみであり、実機起動確認も未実施である。
